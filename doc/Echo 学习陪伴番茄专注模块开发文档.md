# Echo 学习陪伴番茄专注模块开发文档

> 文档状态：v1.1.0 已完成实现与真机验收。
>
> 目标版本：v1.1.0。
>
> 更新时间：2026-08-12（Asia/Shanghai）。

## 1. 功能概述

Echo 新增一个独立的“学习陪伴 / 番茄专注”页面，为用户提供一段不依赖聊天的共同学习时间。

用户进入页面后选择专注时长并开始学习。页面持续展示 Echo 的动态人物视频、剩余时间和简单状态，不打开聊天输入框，也不要求用户与 Echo 对话。专注结束后由手机本地提醒，页面展示本轮实际学习时长，并将结果同步到服务端；正常完成时，Echo 可以通过聊天框发送一条不要求回复的祝贺消息。

本功能的核心不是效率统计，而是制造一种轻量的“Echo 正在旁边陪我学习”的在场感：

```text
选择一段时间
  -> Echo 出现并安静陪伴
  -> 用户专注学习
  -> 本地计时到点提醒
  -> 展示本轮完成结果
```

## 2. 产品定位与非目标

### 2.1 产品定位

产品名称暂定：`一起学习`。

一次番茄专注被称为一段“学习陪伴时段”，而不是一个任务或打卡任务。

Echo 在本页面的表现：

- 安静、稳定、持续在场；
- 不主动发起聊天；
- 不用夸张话术催促用户；
- 不把学习过程游戏化为积分、等级或排名；
- 不根据一次未完成推断用户懒惰或失败。

### 2.2 第一版非目标

- 不做普通待办事项或课程管理系统；
- 不做屏幕使用监控、摄像头监督或防离开机制；
- 不做多人自习室；
- 不做语音陪学或实时语音播报；
- 不依赖聊天 Agent 维持倒计时；
- 不要求用户在专注过程中回复 Echo；
- 不做页面内的聊天对话；正常完成后的祝贺消息是一次性结果通知，不开启新的对话回合；
- 不把每一轮专注自动写入长期记忆；
- 不承诺所有 Android 厂商在用户强制停止 APP 后仍能准时提醒。

## 3. 用户入口与页面范围

### 3.1 入口

第一版提供独立页面入口，不把专注界面嵌入聊天页面。

推荐入口：

- 首页或主导航中的“一起学习”；
- 聊天页面菜单中的“一起学习”；
- 后续可支持聊天中识别“陪我学习 25 分钟”并跳转到该页面，但不在第一版依赖自然语言创建。

### 3.2 页面状态

同一个路由内使用明确的页面状态切换，不创建多个互相覆盖的弹窗页面。

```text
setup       开始前设置
running     专注进行中
paused      已暂停
completed   正常结束
ended_early 提前结束
empty       尚无历史记录
```

## 4. 页面交互设计

### 4.1 开始前设置页 `setup`

页面内容从上到下建议为：

1. Echo 动态视频区域；
2. 一句固定状态文案，例如“我在这，陪你学一会儿”；
3. 专注时长选择：`25 分钟`、`50 分钟`、`自定义`；
4. 学习内容标签：`背单词`、`刷题`、`看课`、`阅读`、`其他`；
5. 可选的一句短目标，例如“完成第三单元”或“看完这一节课”；
6. 主按钮“开始学习”；
7. 今日累计时长和历史入口。

学习内容标签用于展示和统计。短目标只允许一行简短文本，不进入聊天输入框；是否保存到服务端由用户提交时决定，不能默认为长期记忆。

### 4.2 专注页 `running`

专注页是功能的主要体验页面，建议保持视觉克制：

- Echo 视频占据主要视觉区域；
- 中央或下方展示大号剩余时间；
- 显示当前学习标签和本轮计划时长；
- 主操作为“暂停”；
- 次操作为“结束本轮”；
- 不显示聊天消息列表和文本输入框；
- 不在页面上滚动展示励志语或频繁提示。

视频可以有轻微循环动作，例如呼吸、翻页、写字、看书或眨眼。动作应足够安静，不能造成游戏或直播感。

专注过程中允许用户离开页面，计时仍然继续。返回页面时依据持久化的会话状态恢复，不依据页面内存中的计数器恢复。

### 4.3 暂停页 `paused`

暂停时：

- 倒计时停止；
- 取消原先的本地到点提醒；
- 视频停止或切换为静止画面；
- 显示“继续学习”和“结束本轮”两个操作；
- 不发送服务器主动消息。

第一版不限制暂停次数，也不把暂停次数作为评价指标。后续如发现用户误触或长期挂起，再考虑增加自动过期规则。

### 4.4 结束页 `completed / ended_early`

正常结束时展示：

- “这一轮完成了”；
- 计划时长；
- 实际专注时长；
- 当前学习标签；
- 如果存在短目标，展示短目标；
- “再来一轮”和“结束学习”两个操作。

正常完成后，服务端可以异步向聊天记录写入一条 `focus_completion` 来源的 Echo 祝贺消息，例如“这一轮完成了，先休息一下吧”。这条消息：

- 最多一条；
- 不要求用户回复；
- 不创建主动聊天任务；
- 不调用表情包或语音；
- 不虚构 Echo 观察到用户具体学习行为；
- 发送失败不影响专注会话已经完成。

提前结束时展示：

- “这一轮提前结束”；
- 实际专注时长；
- “再来一轮”和“返回”两个操作。

第一版不强制询问原因，不弹出“为什么没完成”的问卷。若需要反馈，可在后续版本增加三个低负担选项：`完成一部分`、`临时有事`、`今天状态不太好`。

## 5. Echo 动态视频方案

### 5.1 第一版素材形式

当前 APP 只有 `idle_sit.png` 和 `echo_idle.png` 静态人物资源，尚无动态视频播放依赖。产品侧已经准备一条约 6 MB 的 MP4 视频，第一轮真机测试直接使用该文件，不预先合成为 1～3 分钟长视频。

第一版使用随 APK 内置的短循环视频：

- 格式优先考虑 MP4/H.264；
- 画面比例适配手机竖屏页面；
- 当前视频为无音轨 MP4，按现有素材时长播放并循环；循环是否出现画面断点，以真机测试结果为准；
- 视频不依赖网络，不从远程地址临时加载；
- 需提供静态首帧或现有静态人物图作为加载和异常降级资源。

单个 6 MB 视频循环不会按循环次数复制到内存。播放器主要持有压缩文件和少量解码缓冲，因此第一轮优先用真机确认内存、发热、耗电和循环衔接，再决定是否需要重新编码或延长成品视频。

如果最终素材需要透明背景，应单独评估视频编码和 Flutter 播放兼容性。第一版建议使用自带背景的完整画面，降低解码和适配风险。

### 5.2 独立氛围音

雨声和写字声不放入 MP4，而是作为两个独立的本地音频资源加载。目标资源目录为：

```text
app/assets/sound/
  rain.*
  writing.*
```

第一版音频规则：

- `running` 状态同时播放雨声和写字声；
- `paused` 状态暂停两个音轨；
- `completed` 或 `ended_early` 时停止或短暂淡出两个音轨；
- 两个音轨可以分别设置音量，默认雨声低于写字声；
- 音频播放只营造学习氛围，不承担到点提醒；
- 到点默认使用震动，避免氛围音和提醒音混在一起；
- APP 进入后台后，第一版可以暂停氛围音，但计时继续；
- 单个音频加载失败时，另一个音轨和视频仍然继续；
- 音频不依赖网络，也不通过聊天消息传输。

当前工作区尚未检索到 `app/assets/sound/` 目录和音频文件，正式实现前需要补入并登记具体文件名、格式和授权来源。

### 5.3 视频状态

第一版只要求一条“陪学中”循环视频，覆盖 `setup`、`running` 和 `paused` 三个页面状态。

状态表现建议：

| 页面状态 | 视频表现 |
| --- | --- |
| setup | 自动循环，动作较轻，传达“准备陪伴” |
| running | 正常循环，保持稳定在场感 |
| paused | 暂停播放或降低动态，避免暗示仍在学习 |
| completed | 播放结束定格或淡出，显示结果信息 |
| ended_early | 定格或淡出，不使用失望、责备类动作 |

后续可以增加“专注中”和“休息中”两条视频，但不作为第一版门槛。

### 5.4 视频与音频失败降级

视频不能成为页面不可用的前提：

1. 视频加载失败时展示 `echo_idle.png` 或 `idle_sit.png`；
2. 视频解码卡顿时保持静态首帧，不阻塞倒计时；
3. 用户关闭动态效果时使用静态人物；
4. 任一氛围音加载失败时，其他音轨和视频继续播放，不阻塞计时；
5. 视频资源不上传用户数据，也不通过聊天消息传输。

## 6. 计时与提醒设计

### 6.1 计时职责

```text
APP 本地计时器/Android 本地闹钟
  -> 负责剩余时间显示和到点提醒

服务端 Focus Session
  -> 负责保存事实、同步状态、生成统计

Echo Agent
  -> 第一版不参与秒级计时
  -> 后续只可生成开始/结束等陪伴内容
```

番茄计时不能只依赖服务端 Worker、个推或网络连接。服务器推送可以作为“Echo 有新反馈”的补充，但不能作为本地闹钟的唯一保障。

### 6.2 时间计算规则

- 每个会话保存 `started_at`、`planned_duration_seconds` 和 `ends_at`；
- 页面显示的剩余时间由结束时间重新计算；
- 暂停时保存已完成时长，并取消当前到点提醒；
- 继续时创建新的剩余时间段和新的本地提醒；
- APP 从后台恢复时重新计算，不累加页面关闭期间的旧计数器；
- 设备时间异常变化时，优先以当前会话状态和服务端最后同步结果进行校正，并记录异常。

### 6.3 提醒方式

第一版支持：

- 本地通知；
- 到点默认震动；
- 后续可配置系统通知声音；
- APP 前台时的页面内完成提示。

第一版不要求接入厂商离线推送才能完成番茄提醒。个推和厂商通道仍然用于普通主动聊天通知。

### 6.4 后台和异常边界

| 场景 | 预期行为 |
| --- | --- |
| APP 前台 | 倒计时持续更新，到点立即显示完成状态 |
| APP 切后台 | 本地计时继续，本地通知到点提醒 |
| 屏幕关闭 | 本地通知和震动提醒，视频氛围音是否继续由真机能力决定 |
| 暂时断网 | 计时和提醒继续，恢复网络后同步 |
| APP 被正常划掉 | 尝试保留已登记的本地提醒，需真机验证 |
| 用户强行停止 APP | 不承诺提醒到达，重新打开时恢复并标记状态 |
| 手机重启 | 若系统允许，重新登记未结束会话；否则打开 APP 时补偿恢复 |
| 电池极限省电 | 可能延迟系统提醒，需要在设置页说明 |

## 7. 会话状态与数据模型

### 7.1 状态机

```text
draft
  -> running
  -> paused
  -> running
  -> completed

running -> ended_early
paused  -> ended_early
```

终态不可再次变更。用户点击“再来一轮”创建新的会话，不复用旧会话 ID。

### 7.2 服务端实体 `focus_sessions`

建议字段：

| 字段 | 用途 |
| --- | --- |
| `session_id` | 会话唯一 ID |
| `user_id` | 用户归属 |
| `activity_type` | study / reading / homework 等，第一版可固定为 study |
| `activity_label` | 可选的简短学习标签 |
| `planned_duration_seconds` | 计划时长 |
| `actual_duration_seconds` | 实际有效专注时长 |
| `status` | running / paused / completed / ended_early / abandoned |
| `started_at` | 开始时间 |
| `ended_at` | 结束时间 |
| `last_paused_at` | 最近暂停时间 |
| `client_timezone` | 用户本地时区 |
| `client_message_id` | 可选幂等键 |
| `created_at` / `updated_at` | 审计时间 |

学习内容标签和时长属于用户数据，必须按用户权限过滤。删除账号时删除；清空聊天时不删除，避免和聊天清理语义混淆。

### 7.3 是否进入长期记忆

第一版不将单轮学习事实自动写入长期记忆。每日来信可以读取当天的专注汇总，但只引用真实完成的会话数据。

例如：

```text
昨天完成 2 轮学习，共 50 分钟
```

可以作为每日来信证据；但不应自动生成“用户每天都坚持学习”这类长期结论。

后续如果希望 Echo 在结束后发送正式聊天消息，再单独设计“学习陪伴结束事件”，不要让本地计时直接写聊天表或直接调用推送。

## 10. API 草案

```text
POST /study-focus/sessions
PATCH /study-focus/sessions/{session_id}
POST /study-focus/sessions/{session_id}/pause
POST /study-focus/sessions/{session_id}/resume
POST /study-focus/sessions/{session_id}/finish
GET /study-focus/sessions
GET /study-focus/summary/today
```

建议：

- 开始、暂停、继续、结束接口都支持幂等；
- APP 断网时将事件留在本地，恢复网络后按顺序补交；
- 服务端拒绝不属于当前用户的会话；
- 重复结束请求返回同一个终态，不生成重复统计；
- 服务端不接受客户端任意篡改已完成时长，按事件和时间范围进行基本校验；
- API 不触发聊天 SSE，第一版页面只通过会话 API 和本地状态更新。

## 11. 视频与计时解耦原则

视频播放和计时必须彼此独立：

- 视频卡住时，倒计时继续；
- 视频加载失败时，静态人物继续陪伴；
- 页面切后台时，视频可以暂停，计时不能暂停；
- 页面恢复时，视频从当前状态重新播放；
- 用户暂停专注时，视频和计时同时进入暂停状态；
- 本地通知失败时，会话仍可在重新打开 APP 后恢复。

这样才能保证“氛围效果失败时，核心功能仍然可用”。

## 12. 隐私、安全与关系边界

- 学习记录只能被当前用户读取；
- 锁屏通知不显示学习内容，默认只显示“这一轮学习结束了”；
- 不采集摄像头、麦克风或屏幕内容；
- 不根据学习时长自动增加关系阶段；
- 不因为用户提前结束而发送责备、内疚或挽留话术；
- 用户可以删除单条学习记录或全部学习记录；
- 关闭通知后，页面内仍显示结束状态；
- 关闭动态人物后，使用静态 Echo，不影响计时。

## 13. 开发分阶段

### P0：产品和资源确认

- 确定页面名称和入口位置；
- 确定 25/5、50/10、自定义时长；
- 确定固定学习标签和可选短目标；
- 接入现有约 6 MB 的 Echo 陪学循环视频；
- 确定完整背景 MP4、画面比例和静态降级图；
- 到点默认使用震动，视频保留雨声和写字声；
- 确定正常完成后发送一条 Echo 聊天祝贺消息。

### P1：页面与本地计时

- 完成独立页面；
- 完成 setup/running/paused/completed/ended_early 状态；
- 完成本地持久化和页面恢复；
- 完成本地到点提醒；
- 接入动态视频和静态降级；
- 核心计时不依赖后端，断网时也能完成一次完整计时；
- 页面结束结果先在本地可靠展示。

### P2：服务端记录与同步

- 增加 `focus_sessions` 数据表和会话 API；
- 同步开始、暂停、继续和结束事件；
- 增加今日汇总和历史记录；
- 实现断网事件补交和重复请求幂等；
- 正常完成时最多触发一条 `focus_completion` Echo 祝贺消息；
- 增加用户删除和权限隔离测试。

### P3：Echo 陪伴增强

- 在开始、暂停和结束页面增加版本化静态文案；
- 将真实学习汇总作为每日来信可选证据；
- 正常完成后的聊天祝贺消息按一次性 `focus_completion` 事件交付；
- 增加休息时段和更多人物视频状态。

## 14. 测试与验收标准

### 14.1 页面验收

- 独立页面可以从首页和聊天菜单进入；
- 不显示聊天输入框和聊天消息列表；
- 大号倒计时在常见手机尺寸不溢出；
- 视频循环播放，首帧和静态降级正常；
- 暂停、继续、结束操作状态明确且不可重复提交；
- 页面旋转或重新进入后不会创建重复会话。

### 14.2 计时验收

- 前台 25 分钟会话按时结束；
- 后台和锁屏后仍能恢复正确剩余时间；
- 暂停期间不继续扣除有效学习时长；
- 断网时可以完成并在恢复网络后同步；
- APP 被系统回收后重新打开能恢复状态；
- 重复结束和重复同步不会产生重复记录；
- 正常划掉 APP、重启手机、极限省电和强行停止分别进行真机验证并记录差异。

### 14.3 体验验收

- Echo 人物在场感明显，但不会频繁打扰；
- 视频加载失败时用户仍能完成学习；
- 提前结束不会让用户产生被评价或被责备的感觉；
- 结束反馈以事实为基础，不虚构 Echo 真的“看见”用户学习过程；
- 学习记录能帮助用户回顾，但不会变成压力型打卡。

## 15. 产品审核结论

本轮已确认：

1. 页面名称使用“**一起学习**”；
2. 学习内容使用固定标签，并允许填写一句短目标；
3. 专注时长支持 `25/5`、`50/10` 和自定义；
4. Echo 使用带完整背景的 MP4，不要求透明背景；
5. MP4 不包含音频，雨声和写字声从 `app/assets/sound/` 独立加载；
6. 到点默认震动；
7. 用户提前结束时只记录实际时长，不强制询问原因；
8. 第一版在专注页展示结束结果，同时允许正常完成后由 Echo 通过聊天框发送一条祝贺消息；
9. 今日学习记录纳入每日来信，默认开启；
10. 当前约 6 MB 的 MP4 先直接进行真机循环测试，不预先合成为 1～3 分钟长视频。

## 16. 第一版建议结论

建议先确认以下范围后再进入实现：

```text
独立“一起学习”页面
  + 25/5、50/10、自定义专注时长
  + 本地可靠倒计时和到点通知
  + Echo 动态循环 MP4
  + 独立雨声和写字声
  + 暂停、继续、提前结束
  + 固定学习标签和可选短目标
  + 今日学习时长记录
  + 正常完成后的单条 Echo 祝贺消息
  + 视频和通知失败时的静态/页面降级
  - 不做聊天输入
  - 不做专注过程中的聊天对话
  - 不做复杂任务管理
  - 不做积分、连续打卡和排名
```

这个范围可以先验证最重要的问题：用户是否愿意在 Echo 的陪伴下持续学习，而不是先把它做成一个完整的学习管理系统。

## 17. 开发与发布门禁

本功能采用本地优先的开发和发布流程：

1. 先在本地完成 APP、视频、音频和本地计时功能；
2. 后端接口如有需要，只在本地开发环境和本地数据库验证；
3. 不自动部署到生产服务器；
4. 不自动构建、上传或发布新 APK；
5. 开发者使用真机完成前台、后台、锁屏、断网、暂停、恢复、视频循环和双音轨测试；
6. 只有用户确认真机测试通过后，才进入后端部署和新 APK 发布流程；
7. 发布前仍需执行架构检查、后端测试、Flutter 分析、Flutter 测试和版本验收。
