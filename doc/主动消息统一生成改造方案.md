# 主动消息统一生成改造方案

更新日期：2026-11-27。状态：**部分实施**。本文替代旧的两条主动正文生成路径，实施时以本文和用户当前要求为准。

已完成：
- `render_persona_digest`，念头生成器引用同一人设摘要；念头 schema 去掉 `draft_text`。
- presence 建 goal 不再写 `draft_text`，条件改为 `shareable or salience >= 阈值 or action`。
- `prepare` 新增 `proactive_brief/plan/skip_planner`；A 路无动作 branch 已改走 `prepare`。
- 动作分支改用 `chat.public.build_proactive_writer_messages` 共享 writer 提示，并接 `guard_dialogue_reply`。
- 失败/空输出 suppress，不再投递 `draft_text` 兜底文案。

未完成：`draft_text` 公共参数/端口/历史字段清理（当前只保留历史读取，新写入恒空）；真实 presence goal + worker 链路验收。

## 1. 背景

主动消息现在有两条互不相干的正文生成路径：

| 入口 | 决定发不发 | 正文谁写 | 人设 | 风格检查 |
| --- | --- | --- | --- | --- |
| presence 自发（念头） | 念头一次调用同时决定 | `draft_text` 直接投递；带动作时用裸 agent | **无** | **无** |
| 定时任务（schedule） | planner | writer（11 层提示） | 完整 | 有 |

生产实况（2026-11-27 查证）：

- `proactive_goals`：agenda 12、presence 7、memory 2；job 全部来自 goal。
- 7 条 presence 草稿全部被 `proactive_disabled` 抑制，没有一条经过风格检查。
- 13 个 goal job 因 `worker_lease_exhausted` 失败，与正文生成无关。
- 定时入口在 21:09 首次跑通：planner → writer → 投递「时间到了，喝水」，一次成功。

结论：**用户可见的主动正文有两条质量完全不同的产线**，而用户要求的是"念头和消息一致、人格一致"。

## 2. 目标与非目标

### 目标

1. 主动正文只有一份生成器：同一个 `prepare(conversation_mode="proactive")`，同一套提示层、同一套风格检查与兜底。
2. 念头和消息语义一致：念头原文作为写作素材进入简报，不允许"念头想 A、消息说 B"。
3. 念头本身带人格：念头生成器引用与 writer 同源的短版人格摘要。
4. `presence_thoughts.text` 不变，App「内心念头」页面不受影响。
5. 不扩大 feature 依赖环，不新增 future 占位。

### 非目标

- 不合并触发层：presence 的预算、去重、连续未回复降档与 schedule 的静默时段、额度保持各自语义。
- 不改 planner 的职责与提示（它只服务定时/策略入口）。
- 不改 App 协议：`GET /presence/me` 字段不变。
- 不动画像层内容（用户后续单独修），本次只做"主动场景不注入画像"的开关。

## 3. 目标架构

```
① 触发（两套，保留）
   presence tick ──► thought ──► goal(intent=念头, plan, action_intent)
   schedule       ──► planner(要不要发/主题/语气/事实)
        │
② 意图（统一为 prepare 的输入参数，不新建跨 feature DTO）
   user_id, intent(=念头或提醒目标), plan, action_intent, trigger_type
        │
③ 生成（同一套提示与后处理）
   GenerateChatReply.prepare(conversation_mode="proactive", ...)
     ├─ render_prompt_layers(proactive, include_user_profile=False)
     ├─ 写作简报 = 主题/语气/允许事实/念头原文/计划
     ├─ planner 可选：入口 B 调，入口 A 跳过（skip_planner=True）
     └─ agent → 交付计划 → 风格检查 → 兜底

   带动作的分支（需要 tool_results 判断成败）保留 agent 直调，但：
     ├─ messages 用同一个 render_prompt_layers + 同一个简报构建函数
     └─ 返回前跑同一个风格守卫（见 4.8）
        │
④ 交付（已共用）
   persist_delivery → 微信 → chat.delivery.created → 通知 Outbox
```

## 4. 详细设计

### 4.1 人设单源、两种渲染形式

`features/assistant_persona/infrastructure/default_persona.py` 保持唯一内容源。

`shared/prompting/renderer.py` 新增：

```python
def render_persona_digest(persona: AssistantPersona, *, maximum_tokens: int = 240) -> str:
    """渲染给非对话场景引用的短版人格，内容取自同一份 AssistantPersona。"""
```

输出内容：名字 + 角色一句 + traits 前两条 + conversation_principles 前两条 + forbidden_claims 一条，控制在 240 token 内。

使用方：

- writer：继续用完整 `render_assistant_persona`（不变）。
- 念头生成器：`_SYSTEM_PROMPT` 改为固定说明 + `render_persona_digest(...)`，在模块初始化时拼接，不再写死第二份人格。
- planner：不加人设（纯决策）。

这样三处人格口径同源，且没有新增需要注册的资产目录（符合规范 §4「不得预建空目录或占位文件」）。

### 4.2 `GenerateChatReply.prepare` 参数扩展

```python
async def prepare(
    self,
    *,
    user_id: str,
    message: str,
    conversation_id: str,
    conversation_mode: str = "chat",
    # ... 现有参数保持不变 ...
    proactive_intent: str = "",
    proactive_force_send: bool = False,
    proactive_brief: str = "",            # 新增：念头原文（写作素材，不原样输出）
    proactive_plan: str = "",             # 新增：念头自带的计划
    proactive_skip_planner: bool = False, # 新增：上游已完成"要不要发"的判断
) -> PreparedChatReply:
```

现有行为不变：定时入口仍传 `proactive_intent` / `proactive_force_send`，不传 `skip_planner`，planner 照常运行。

`skip_planner=True` 时跳过 `self.proactive_planner.decide(...)`，由 `prepare` 内部按 `proactive_brief` / 是否有动作合成 decision（见 4.3）。

### 4.3 写作简报

`features/chat/application/generate_reply.py::_build_proactive_writer_turn` 的签名扩展为：

```python
@staticmethod
def _build_proactive_writer_turn(
    base_messages: list[dict[str, str]],
    safe_facts: dict[str, str],
    decision: ProactiveDecision,
    *,
    brief: str = "",
    plan: str = "",
) -> list[dict[str, str]]:
```

简报新增两段（仅当非空时出现）：

```
你刚才的内心想法（写作素材，不是要你原样复述；表达同一件事即可）：
{brief}
这次原本打算：{plan}
```

约束后面补一句：

```
正文必须与上面的事实和内心想法一致，不得换成另一件无关的事。
```

入口 A 的 `decision` 由代码合成（不调模型）：

```python
ProactiveDecision(
    action=ProactiveAction.SEND,
    topic="casual_check_in" if not goal.action_intent else "share_presence",
    tone="gentle",
    safe_fact_ids=("task_intent", "current_day_period"),
    reason="presence_thought",
)
```

`topic` / `tone` 只影响简报措辞，不再由模型判断。

### 4.4 画像层留空

`render_prompt_layers` 增加参数：

```python
include_user_profile: bool = True,
```

为 `False` 时**不追加** `USER_PROFILE` 层（现在的行为是传 `None` 也会渲染"你还不太了解他"的采集提示）。

`render_prompt_layers` 的 proactive 调用传 `include_user_profile=False`；chat / call / daily_letter 保持 `True`。

### 4.5 入口 A 的两条分支

`features/proactive_chat/application/worker.py::_deliver_goal_job` 按是否有 `action_intent` 分两条，**两条都必须拿到同一套提示和后处理**。

#### 4.5.1 无动作：直接走统一生成器

删除 `segments = (draft,)` 直投分支，改为：

```python
prepared = await self.reply_generator.prepare(
    user_id=goal.user_id,
    message=goal.intent,                 # 只用于路由，不进 prompt（现有行为）
    conversation_id=conversation_id,
    conversation_mode="proactive",
    proactive_intent=goal.intent,
    proactive_plan=goal.plan,
    proactive_force_send=True,           # goal 已由念头判断要说
    proactive_skip_planner=True,
    proactive_brief=goal.intent,
)
```

`goal.intent` 已经是念头原文（`presence_service._maybe_create_goal` 传 `intent=thought.text`），不需要新增数据库字段。

#### 4.5.2 有动作：保留 agent 直调，共享提示与守卫

需要 `tool_results` 判断 `success / partial / failed`，而 `PreparedChatReply` 不携带工具结果，因此这一步不强行塞进 `prepare`。

共享提示由 `chat/public.py` 新增的公开入口提供（避免 worker 导入 chat 的内部实现）：

```python
# features/chat/public.py
async def build_proactive_writer_messages(
    *,
    user_id: str,
    conversation_id: str,
    brief: str,
    plan: str = "",
    action_intent: str = "",
    sticker_intent: str = "",
) -> list[dict[str, str]]:
    """给需要工具执行的主动动作准备与 writer 相同的提示层。"""
```

worker 侧：

```python
agent_messages = await build_proactive_writer_messages(
    user_id=goal.user_id,
    conversation_id=conversation_id,
    brief=goal.intent,
    plan=goal.plan,
    action_intent=goal.action_intent,
)
result = await run_chat_agent(
    user_id=goal.user_id,
    message="根据后端批准的主动聊天安全摘要生成自然正文。",
    messages=agent_messages,
    conversation_id=conversation_id,
    conversation_mode="proactive",
    tools_enabled=True,
    tool_scope=tool_scope,
)
```

该入口内部调用 `build_chat_context(conversation_mode="proactive")` 与 `_build_proactive_writer_turn`，与 `prepare` 共用同一份实现，不再有一条 system 的裸提示。

动作分支在投递前必须跑 4.8 的风格守卫。

### 4.8 风格守卫复用

`features/chat/domain/dialogue_style.py` 的 `find_dialogue_style_violations` 与 `apply_dialogue_fallback` 已是纯函数。新增一个薄封装供 worker 使用：

```python
# features/chat/domain/dialogue_style.py
def guard_dialogue_reply(
    reply: str,
    user_message: str,
    *,
    allow_empty: bool = False,
    pause_followup_questions: bool = False,
    suppress_repeated_greeting: bool = False,
    grounded_weekday: str = "",
) -> tuple[str, tuple[str, ...]]:
    """返回（清洗后的回复，命中的违规类型）；无违规时原样返回。"""
```

`GenerateChatReply.prepare` 与 worker 的动作分支都调它，保证两条路同一套判定。

### 4.9 draft_text 退役

- `presence/infrastructure/thought_generator.py`：输出 schema 删除 `draft_text` 字段；`_SYSTEM_PROMPT` 删除相关要求；`ThoughtDraft.draft_text` 保留字段但恒为空，第二阶段删除。
- `presence/application/presence_service.py`：`_maybe_create_goal` 不再传 `draft_text`；建 goal 条件从 `draft or action` 改为 `shareable or salience >= 阈值 or action`。
- `proactive_chat.domain.entities.ProactiveGoal.draft_text` 保留只读（历史数据），新写入恒为空；表列不删。
- 失败兜底：删除 `goal.draft_text` 兜底文案（"本来想…，这次没做成。"这种无人格文案会破坏一致性）。改为：生成失败或空交付时 `suppress_job`，写内部记录，不投递。与 `doc/Echo v1.0.9 当前功能与扩展基线.md`「主动 Agent 空输出 → suppressed，不消耗额度」一致。

### 4.10 一致性保证

- 念头和消息共享同一份人格摘要（4.1）。
- 消息的写作简报携带念头原文和计划（4.3）。
- 两条入口共用同一个风格检查与兜底（`guard_dialogue_reply`），A 路从此不再是法外之地。
- 念头与最终消息的差异属于措辞层面，语义必须一致；如出现偏离，先查简报是否被截断。

## 6. 实施步骤

每一步独立可验证，失败可单独回滚。

1. **人设摘要 + 画像开关**：`render_persona_digest`、`include_user_profile`。改完跑 `test_prompt_renderer`。
2. **念头接人格**：thought_generator 引用摘要；`draft_text` 从 schema 移除。观察念头文本是否带上人格口径（生产 tick 或本地脚本）。
3. **prepare 扩展 + A 路无动作分支切换**：worker 无动作 goal 改走 `prepare`，保留 `draft_text` 字段但不读。用本地库跑一条 goal，对比改造前后消息。
4. **动作分支共享提示**：新增 `chat/public.build_proactive_writer_messages`，替换 `_execute_goal_actions` 的单条 system，并接上 `guard_dialogue_reply`。
5. **草案退役与兜底调整**：删除 draft 写入与兜底投递，失败静默。跑全量后端测试与架构检查。

每步完成后：`python -B scripts/check_architecture.py`、`python -m pytest Echo-backend/tests -q`、`python -m ruff check <改动文件>`。

## 8. 回滚

- 代码回滚：A 路恢复 `draft_text` 直投需要同时恢复 `thought_generator` 的 draft 输出；两步在同一分支回滚。
- 数据：本方案不删表列、不改历史数据，`proactive_goals.draft_text` 与 `presence_thoughts.draft_text` 保留。
- 开关：可在 worker 里用一个配置项暂时把 A 路切回直投（仅回滚期使用，不作为长期开关；如无实际回滚需求则不引入该配置）。

## 9. 风险与取舍

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| A 路每次"想说话"多一次模型调用 | 成本上升；后台 worker，不影响用户交互延迟 | 生产数据 32 念头 / 11 shareable，日均十余次，可接受 |
| 风格兜底可能改写念头语气 | 消息与念头措辞差异变大 | 简报明确"表达同一件事"，观察后再调 |
| 念头生成器引入人格摘要后，念头变长 | App 展示与 token 预算 | `render_persona_digest` 限 240 token |
| 老 goal 带 draft 但无念头素材 | 重生成时素材不足 | 用 `goal.intent` 兜底（agenda goal 的 intent 是活动标题） |
| 失败静默后用户什么都收不到 | 体验 | 主动消息本就有"没话说就不说"的语义；失败写内部记录便于排查 |
