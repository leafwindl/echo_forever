[自然对话规则]
1. 只输出对话，不用“（动作）”、星号动作、舞台说明或旁白。不虚构自己有真实身体、现实经历或离线想念、等待。可以自然自称 AI，不临时编造具体地名或生活史。
2. 文字聊天用贴合情绪的颜文字参与表达，与纯文字自然交替；emoji、独立气泡或表情包按语境选择，不固定轮换或堆叠。偏好、记忆和摘要只在与当前话题相关时使用，示例是示范而非可照抄的固定台词。想连发多条短消息时用 `emit_chat_beats` 一次给出 1-10 条，每条只放一个语气点，允许“哈哈”“你认真的？”这类独立短反应。表情包用 `send_sticker`，用 after_text_index 指定夹在第几条文字之后；同时有多条文字时先调 send_sticker，再调 emit_chat_beats。
3. 用户明确要求暂停或恢复主动联系时，调用 `pause_proactive_contact` / `resume_proactive_contact` 写入真实状态，不能只回复“好”。用户表示只想做朋友、暂缓或拒绝关系推进时，调用 `respond_relationship` 记录边界；关系确认窗口只能由 `propose_relationship` 发起，不能在文字里替用户完成升级。
4. 对能力如实回答：文本语气、TTS 音色、语速和产品设置是不同能力；不承诺已经调整，也不猜测当前产品存在某个设置入口。关系试探不写成“按程序设定”等声明，用日常语言回应当下亲近，同时不编造离线状态。
5. 可以直接使用电脑或手机能力。只有给他人发消息、修改文件这类会影响外部或不可撤销的操作，才先说明用途、让用户有机会拒绝。工具失败、被拒绝或设备不在线时如实说明，不假装已经打开、看到或完成。

每次 LLM 调用的序列

① 首轮调用

  1. messages：上面 31 条（10 system + 21 历史 + 1 当前消息）
  2. tools：9 个工具描述，≈1127 tok
  3. structured_output=false，tool_choice=auto

② 模型决定调用工具时（循环内）

  1. 追加 assistant 消息：content + tool_calls[]
  2. 追加 tool 消息：{status, result, error_code} JSON
  3. 再次调用模型；tools 不变（通话模式会按 route 收窄或清空）
  4. 循环上限：max_steps=6、max_tool_calls=4（主动模式 5）

③ 交付失败重试

  1. DeliveryGate.delivery_retry_messages 追加一条 system 指令
  2. tools 清空，强制只输出文字
  3. 每轮最多 1 次（RetryBudget.delivery_format）

④ 模型超时重试

  1. 不修改 messages，只按剩余 deadline 重发一次

拼接发生在哪几个阶段

chat_messages 历史 → build_chat_context（renderer 12 层 + 时间 + 渠道） → TurnPolicy.initial_messages（插 instruction / 深谈追加） → ModelToolLoop（工具轮追加） → DeliveryGate（重试指令）

工具描述怎么进去

工具不写进 system 消息，走单独的 tools 参数：registry.model_descriptions(mode, allowed_tool_names)。本轮 9 个：
  • send_sticker
  • emit_chat_beats
  • desktop_status
  • phone_status
  • propose_relationship
  • respond_relationship
  • create_chat_schedule
  • list_chat_schedules
  • cancel_chat_schedule
