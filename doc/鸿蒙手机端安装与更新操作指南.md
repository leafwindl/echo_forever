# Echo 鸿蒙手机端安装与更新操作指南

核对日期：2026-10-23。开发阶段默认使用 USB 覆盖更新，不再要求先完成华为后台分发配置。

## 当前默认：USB 更新

手机开启并允许 USB 调试，客户端构建签名完成后，在项目根目录执行：

```powershell
& .\harmony_app\scripts\install-usb.ps1
```

脚本读取实际 HAP 的应用身份与版本，覆盖安装、核对版本并启动；不卸载、不清数据。多台设备使用 `-DeviceId` 指定。2026-10-23 已在连接手机上核对 `1.1.8 (10108)` 并启动成功。后端人设变更通过服务器部署生效，不需要仅为人设再安装一次包。

下文保留为以后确实需要无 USB 分发时的材料准备说明，不是当前开发的前置条件。

当前已经准备好服务端下载与 1.1.8 调试包，但手机端安装入口尚未完成。现有包使用 `debug` Profile，不能直接当作内部测试分发包。旧客户端通过 `viewData` 打开下载文件，已出现无法进入安装程序的问题。

## 可选：无 USB 分发的准备

1. **选择同一个鸿蒙应用。** 登录华为开发者中心，找到 Echo，确认 Bundle Name 为 `cn.echoaiforever.echo_app.dev`。先确认控制台能否为此应用创建“内部测试”Profile；如果没有该选项，记录账号类型和页面可选项，交给开发端确认适用的测试渠道。
2. **准备配套的发布签名材料。** 按控制台和官方指引准备发布证书、对应的私钥文件。已有配套材料可以复用；现有“调试证书／调试 Profile”不作为内部测试分发凭据。
3. **复用已经登记的测试设备。** 本机已从当前签名 Profile 提取出 1 个设备 UDID，保存在 [device-udids.txt](../data/harmony-update-handoff/device-udids.txt)。在后台核对该设备，已有记录则直接选择；没有记录再添加。该文件仅保存在本机、被 Git 忽略，没有上传到 GitHub。
4. **申请内部测试 Profile。** 选择上述应用、配套发布证书与测试设备，生成并下载“内部测试”Profile。不要用改文件名的方式把调试 Profile 当作内部测试 Profile。
5. **告诉开发端材料的本地路径。** 需要 `.p7b` Profile、配套 `.cer` 发布证书和 `.p12` 私钥文件。可以放在 `data/harmony-update-handoff/signing/`，该位置已被现有 Git 规则忽略。私钥密码留在本机交互输入，不写进文档或聊天。

这套操作不需要为获取 UDID 再连接 USB。如果实际使用的手机不是现有 Profile 中的设备，需要另外登记正确设备。

## 材料齐全后，开发端完成的工作

- 核对 Profile 类型、应用、设备授权和签名材料，重新构建并签名；先检查与已安装调试版的覆盖兼容性。如系统提示签名冲突，不自动卸载现有应用。
- 根据实际产物生成应用描述文件，并使用官方工具签名。应用包、图标和描述文件使用同一部署域名，提供 HTTPS、HEAD 文件大小响应与 Range 分片下载。
- 生成安装页面：用户在华为浏览器点击后，通过 `store://enterprise/manifest?url=...` 交给系统下载安装。当前没有有效内部测试签名，因此尚未生成可安装的描述文件或按钮。
- 将后续应用内更新接到官方文档支持的 `openLink` 安装入口，替换当前打开本地 HAP 文件的做法；不再重复下载后尝试普通文件查看器。

## 你在手机上的验收

1. 在华为浏览器打开最终安装页面，点击安装，确认能够出现系统下载安装流程。
2. 完成安装后，在应用内核对新版本号，再登录原账号查看聊天记录和关系设置。
3. 再次检查更新，确认不会把同一版本重复当作新版本，也不会显示未实际完成的安装成功。
