# Echo 上线安全与运维说明

## 1. 正式 Token 鉴权

`POST /login` 会返回：

```json
{
  "user_id": "wx_xxx",
  "access_token": "xxx",
  "token_type": "bearer",
  "expires_in": 2592000
}
```

小程序后续请求会携带：

```http
Authorization: Bearer <access_token>
```

关键配置：

```dotenv
AUTH_TOKEN_SECRET=请替换为足够长的随机密钥
AUTH_TOKEN_EXPIRES_SECONDS=2592000
ENABLE_LEGACY_USER_ID_AUTH=true
```

内部测试确认新版本小程序已经携带 Bearer token 后，服务器可以设置：

```dotenv
ENABLE_LEGACY_USER_ID_AUTH=false
```

关闭后，后端不再信任 body/query/header 中的 `user_id` 作为身份来源。

## 2. 聊天请求串行化

配置：

```dotenv
ENABLE_CHAT_REQUEST_SERIALIZATION=true
```

开启后，同一用户上一条 `/chat/send` 未完成前，再发送消息会返回 `409 Conflict`。前端也会在等待回复期间禁用发送、录音和输入模式切换，避免重复提交。

当前实现是单机内存锁，适合 MVP 和单实例 Docker 部署。未来多实例部署时，应替换为 Redis 锁。

## 3. SQLite 备份与恢复

备份：

```bash
python -B scripts/backup_sqlite.py
```

指定数据库和备份目录：

```bash
python -B scripts/backup_sqlite.py --db data/echo_memory.db --backup-dir data/backups
```

恢复前先停止后端服务或 Docker 容器，然后执行：

```bash
python -B scripts/restore_sqlite.py data/backups/echo_memory_YYYYMMDD_HHMMSS.db
```

恢复脚本会：

- 校验备份文件完整性。
- 给当前数据库自动创建 `pre_restore` 备份。
- 清理旧 WAL/SHM 旁路文件。
- 恢复后再次执行完整性校验。

## 4. 日志脱敏

后端启动时会安装全局日志脱敏过滤器，避免以下内容进入日志：

- `Authorization: Bearer ...`
- `access_token`
- `secret`
- `openid`
- 微信临时 `js_code`
- URL 中常见 token/key 参数

业务代码也应避免直接打印聊天正文、ASR 识别文本和第三方模型响应正文。需要排查问题时，优先记录状态码、长度、用户 ID、任务 ID、消息 ID 等结构化元信息。
