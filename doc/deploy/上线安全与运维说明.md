# Echo 上线安全与运维说明

## 1. 正式 Token 鉴权

`POST /login` 会返回：

```json
{
  "user_id": "wx_xxx",
  "access_token": "xxx",
  "token_type": "bearer",
  "expires_in": 2592000
}
```

小程序后续请求会携带：

```http
Authorization: Bearer <access_token>
```

关键配置：

```dotenv
AUTH_TOKEN_SECRET=请替换为足够长的随机密钥
AUTH_TOKEN_EXPIRES_SECONDS=2592000
```

后端不信任 body、query 或自定义 Header 中的 `user_id`，用户身份只来自 Bearer Token。

小程序登录失败时不会再退化为无 Token 的匿名身份，而是阻断业务操作并提供重新登录入口。

## 2. 聊天请求串行化

配置：

```dotenv
ENABLE_CHAT_REQUEST_SERIALIZATION=true
```

开启后，同一用户上一条 `/chat/send` 未完成前，再发送消息会返回 `409 Conflict`。前端也会在等待回复期间禁用发送、录音和输入模式切换，避免重复提交。

当前实现是单机内存锁，适合 MVP 和单实例 Docker 部署。未来多实例部署时，应替换为 Redis 锁。

## 3. 请求与成本保护

当前单实例后端提供内存级滚动窗口和 UTC 自然日配额：

```dotenv
CHAT_MESSAGE_MAX_CHARS=2000
CHAT_RATE_LIMIT_REQUESTS=10
CHAT_RATE_LIMIT_WINDOW_SECONDS=60
CHAT_DAILY_REQUEST_LIMIT=100
GLOBAL_DAILY_CHAT_REQUEST_LIMIT=1000

LOGIN_RATE_LIMIT_REQUESTS=10
LOGIN_RATE_LIMIT_WINDOW_SECONDS=60
LOGIN_DAILY_REQUEST_LIMIT=100
GLOBAL_DAILY_LOGIN_REQUEST_LIMIT=1000

VOICE_UPLOAD_MAX_BYTES=10485760
VOICE_RATE_LIMIT_REQUESTS=5
VOICE_RATE_LIMIT_WINDOW_SECONDS=60
VOICE_DAILY_REQUEST_LIMIT=30
GLOBAL_DAILY_VOICE_REQUEST_LIMIT=300
```

触发限制时接口返回 `429` 和 `Retry-After`。语音超过应用限制时返回 `413`。Nginx 还应设置 `client_max_body_size 11m`，示例见 `deploy/nginx/echo-api.conf.example`。

内存配额会在进程重启后重置，只适合当前单实例小范围体验版。体验测试前仍应在 LLM、ASR、TTS 服务商控制台设置账户预算和告警；多实例或正式发布时迁移到 Redis/数据库计数。

## 4. API 暴露范围

1.0 已删除运行时提示词和管理调试接口。体验版和正式版应设置：

```dotenv
ENABLE_API_DOCS=false
```

这会关闭 `/docs`、`/redoc` 和 `/openapi.json`。生产路由应以根目录 README 的 1.0 HTTP 契约为准。

## 5. 数据库备份与恢复

当前运行数据库为 PostgreSQL + pgvector。自动备份由独立的 `echo-postgres-backup` 容器负责，不进入 FastAPI 业务进程。

默认策略：

- 容器启动后立即执行一次备份。
- 每 86400 秒执行一次 `pg_dump`。
- 使用 custom dump 格式并通过 `pg_restore --list` 校验。
- 备份写入 `data/backups/postgres/`。
- 自动删除超过 7 天的备份。

配置位于根目录 `.env`：

```dotenv
POSTGRES_BACKUP_INTERVAL_SECONDS=86400
POSTGRES_BACKUP_RETENTION_DAYS=7
```

启动与查看：

```bash
docker compose up -d echo-postgres-backup
docker compose logs -f echo-postgres-backup
ls -lah data/backups/postgres
```

手工立即备份：

```bash
docker compose run --rm --entrypoint /bin/sh echo-postgres-backup \
  /scripts/postgres_backup.sh once
```

恢复会重建目标数据库，必须先停止后端和自动备份服务：

```bash
docker compose stop echo-backend echo-postgres-backup
docker compose run --rm \
  -e CONFIRM_POSTGRES_RESTORE=echo \
  --entrypoint /bin/sh \
  echo-postgres-backup \
  /scripts/postgres_restore.sh /backups/<backup-file>.dump
docker compose up -d echo-postgres-backup echo-backend
```

1.0 不读取或迁移 SQLite。正式备份统一围绕 PostgreSQL，并应进一步把备份同步到 COS 等服务器外存储。

## 6. 健康、版本与日志

部署探针：

```text
GET /               # 进程存活
GET /health/ready   # PostgreSQL 可用性，失败返回 503
GET /version        # APP_VERSION / BUILD_REVISION
```

HTTP 中间件记录 method、path、status、duration，不记录 query、body 或聊天正文。

后端启动时会安装全局日志脱敏过滤器，避免以下内容进入日志：

- `Authorization: Bearer ...`
- `access_token`
- `secret`
- `openid`
- 微信临时 `js_code`
- URL 中常见 token/key 参数

业务代码也应避免直接打印聊天正文、ASR 识别文本和第三方模型响应正文。需要排查问题时，优先记录状态码、长度、用户 ID、任务 ID、消息 ID 等结构化元信息。
