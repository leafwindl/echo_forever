# Echo v0.3 电话模式语音服务部署与验收

> 范围：MeloTTS + FunASR 2-pass 流式识别 + TTS 分段播放  
> 状态：代码已实现；真实服务器模型下载、性能和真机听感待验收

## 1. 上线策略

这两个本地模型服务通过 Docker Compose 的 `voice-local` profile 提供，默认不自动启用。未启用时，后端继续使用 EdgeTTS，小程序流式连接失败后自动回退到现有腾讯整段 ASR。

建议先只给内部账号或 1～3 名体验用户启用。FunASR 官方运行时本身较重，MeloTTS 首次还要下载中文模型；服务器资源不足时应拆到独立语音服务器，不要挤占数据库和聊天 API。

## 2. 部署前检查

- Docker 与 Docker Compose 可用，服务器能访问镜像仓库、GitHub、PyPI 和模型仓库。
- 建议至少预留 4 vCPU、8 GB 可用内存和 15 GB 磁盘；与主后端同机时以实测峰值为准。
- 已将 `deploy/nginx/echo-api.conf.example` 中 `/voice/asr/stream` 的 WebSocket 配置同步到公网 Nginx。
- 小程序 request/socket 合法域名均包含当前 HTTPS API 域名。
- 腾讯 ASR 密钥仍保留，用于流式链路失败时降级。

## 3. 配置

在服务器 `Echo-backend/.env` 增加：

```dotenv
TTS_PROVIDER=melotts
TTS_VOICE_ID=ZH
TTS_SPEED=1.0
TTS_SEGMENT_MAX_CHARS=80
TTS_REPLY_MAX_CHARS=600
TTS_AUDIO_MAX_BYTES=10485760
MELOTTS_TIMEOUT_SECONDS=60

VOICE_STREAMING_ASR_ENABLED=true
FUNASR_MODE=2pass
FUNASR_FINAL_TIMEOUT_SECONDS=15
FFMPEG_BINARY=ffmpeg
```

Compose 已把容器内地址设置为：

```dotenv
MELOTTS_BASE_URL=http://echo-melotts:9000
FUNASR_WS_URL=ws://echo-funasr:10095
```

不要把 MeloTTS 或 FunASR 端口直接暴露到公网。

## 4. 启动

```powershell
docker compose --profile voice-local build echo-backend echo-melotts
docker compose --profile voice-local up -d echo-postgres echo-melotts echo-funasr echo-backend
docker compose --profile voice-local ps
docker compose logs --tail 200 echo-melotts echo-funasr echo-backend
```

首次启动会下载模型，耗时明显长于普通发布。模型缓存在 `echo-melotts-models` 和 `echo-funasr-models` volume，普通容器重建不会重复下载。

从后端容器验证 MeloTTS：

```powershell
docker compose exec echo-backend python -c "import urllib.request; print(urllib.request.urlopen('http://echo-melotts:9000/health/ready', timeout=10).read())"
```

确认主后端镜像内 FFmpeg 可用：

```powershell
docker compose exec echo-backend ffmpeg -version
```

## 5. Nginx 与连接验证

更新配置后执行：

```powershell
nginx -t
systemctl reload nginx
```

公网 `/voice/asr/stream` 必须能升级为 WebSocket。无 Token、错误 Token、关闭功能开关时连接都应失败；不要为了排错临时取消鉴权。

## 6. 真机验收

每项至少连续测试 10 次，并记录成功率、端到端耗时和失败原因。

1. 进入电话模式，按住后应立即出现录音反馈，不应等待 WebSocket 建连才开始录音。
2. 连续说 5～15 秒中文，录音过程中应看到短暂的识别文本提示。
3. 松手后最终识别文本应完整，FunASR 2-pass 修正结果应覆盖在线临时结果。
4. Echo 回复包含 2～4 句话时，应拆成多段自然连续播放，顺序不能错乱。
5. 播放中挂断，当前音频和后续分段都应立即停止。
6. 断开 FunASR 服务后再次录音，应自动使用腾讯整段 ASR 并完成对话。
7. 断开 MeloTTS 服务后，应保留文字回复，接口不能因 TTS 失败返回 500。
8. 说满 60 秒、上传超限、频率超限时，客户端应收到可理解提示，后端内存不应持续增长。
9. 两名用户同时电话对话，识别结果和音频不能串话。
10. 检查 Nginx、后端日志，不应出现 Bearer Token、原始音频或完整识别文本。

建议记录以下指标：

- WebSocket 建连时间。
- 第一条 partial 到达时间。
- 松手到 final 的时间。
- 发出聊天请求到第一段开始播放的时间。
- 每段 TTS 合成时间、失败率、CPU 与内存峰值。
- FunASR 降级到腾讯 ASR 的次数和原因。

## 7. 回滚

先将后端配置改回：

```dotenv
TTS_PROVIDER=edge
TTS_VOICE_ID=zh-CN-XiaoxiaoNeural
VOICE_STREAMING_ASR_ENABLED=false
```

然后只重建/重启主后端：

```powershell
docker compose up -d --build echo-backend
docker compose --profile voice-local stop echo-melotts echo-funasr
```

回滚后电话模式仍可使用 EdgeTTS + 腾讯整段 ASR，聊天、人格和记忆数据不受影响。
