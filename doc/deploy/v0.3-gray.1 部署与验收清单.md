## 2. 部署前

- [ ] 记录目标 commit、镜像 tag 和当前 `/version` 返回值。
- [ ] 备份 PostgreSQL，并确认备份可以读取。
- [ ] 保持 `ENABLE_ADMIN_DEBUG_API=false`。
- [ ] 设置 `PROMPT_VERSION=echo-v0.3.0`。
- [ ] 设置 Persona、记忆和摘要预算，初始值分别为 `400/800/800`。
- [ ] 确认体验版仍使用 Bearer Token，`ENABLE_LEGACY_USER_ID_AUTH=false`。

## 3. 数据库迁移

应用启动时会执行幂等 `CREATE TABLE IF NOT EXISTS`。如采用显式迁移流程，在数据库备份后执行：

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f Echo-backend/db/migrations/v0.3.0_user_personas.sql
```

验证：

```sql
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'user_personas'
ORDER BY ordinal_position;
```

- [ ] `user_personas` 表存在且字段完整。
- [ ] `avoid_topics` 为 `jsonb`。
- [ ] `user_id` 是主键。
- [ ] 后端重启后 `/health/ready` 返回 200。

## 4. API 与隔离验收

- [ ] 用户 A 首次 GET 返回默认值和 `is_customized=false`。
- [ ] 用户 A PUT 后再次 GET 返回相同设置。
- [ ] 后端重启后用户 A 设置仍存在。
- [ ] 用户 B GET 不会得到用户 A 的称呼、自述或避开话题。
- [ ] 请求体伪造 `user_id` 不会改变 Token 所属用户。
- [ ] RESET 后只恢复 Persona，不删除长期记忆或聊天记录。
- [ ] 未带 Token 返回 401。

## 5. 小程序与对话验收

- [ ] 聊天页可以进入“个性化设置”。
- [ ] 字段保存、关闭个性化和恢复默认均有明确反馈。
- [ ] `about_user` 最多 300 字，避开话题最多 5 个。
- [ ] 页面不显示原始系统 Prompt 或管理 Token。
- [ ] 使用 `tests/fixtures/natural_dialogue_acceptance_cases.json` 执行 20 条真实模型验收。
- [ ] 动作/旁白格式出现率接近 0，角色脚本格式出现率接近 0。
- [ ] Persona 与长期记忆冲突时，显式 Persona 生效。

## 6. 性能和回滚

- [ ] 复用 v0.2 压测场景记录 P50/P95/P99、错误率和数据库连接数。
- [ ] 聊天 P95 持续高于 8 秒时暂停扩量。
- [ ] 记录带 Persona/记忆与不带时的 Prompt 长度差异。
- [ ] 回滚代码与 `PROMPT_VERSION` 后完成一次聊天请求。
- [ ] 回滚时保留 `user_personas` 表，避免破坏用户数据；除非有单独审批，不执行 DROP TABLE。
