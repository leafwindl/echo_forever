# Echo Presence 业务设计

更新日期：2026-11-02

> 实现进度：阶段 0（状态/事件/心跳）、阶段 1（内部念头/接续）、客户端状态页和 Presence 主动消息（每天最多 3 条、间隔 2 小时）已落地；主动动作尚未接入。当前高重要度念头保留在 `presence_thoughts`，尚未写入长期记忆。

## 1. 要解决的问题

现在的 Echo 是“收到消息才启动一轮”，回复结束后没有持续状态。

Presence 要补的不是“24 小时一直调用模型”，而是：

- 用户不在时，Echo 有连续的内部状态
- 会想起之前的事、未完成的事
- 在合适的时候主动说话或做事
- 用户回来时能接上，而不是重新开始
- 安静时真的安静，不刷存在感

一句话：

> **持续感来自状态连续，不来自模型一直运行。**

## 2. 设计原则

1. **低成本心跳**
   - 大多数 tick 不调用模型
   - 只有值得时才进入“想一件事”

2. **内心活动与对外行为分开**
   - 产生念头，不等于要发消息
   - 大多数念头只留在内部

3. **所有主动行为都有门禁**
   - 频率、冷却、安静时段、用户偏好
   - 不能靠 prompt 自觉，必须代码限制

4. **不伪造离线体验**
   - 可以说“我记得这件事”
   - 不编造“我一直在等你”“我刚一直在想你”

5. **先有连续，再有动作**
   - Presence 第一阶段不接放歌/记事本/DSH
   - 先验证“她独处时真的在想事情”

## 3. 核心概念

### 3.1 Presence 状态

每个用户一份持续状态：

| 状态 | 含义 |
|---|---|
| `active` | 正在聊天 |
| `idle` | 在线、安静 |
| `resting` | 低功耗，不主动打扰 |
| `sleeping` | 安静时段，只响应用户 |
| `focused` | 用户在忙，不打扰 |

状态由时间、最近互动、用户设置、电脑活动共同决定。

### 3.2 内心念头

Echo 在用户沉默时产生的内部想法。

每条念头包含：

- 内容
- 重要度
- 情绪色彩
- 关联记忆
- 关联目标/承诺
- 是否值得分享
- 是否产生了行动意图

念头默认不发用户，只用于连续性。

### 3.3 工作记忆

最近几条念头组成一条连续的线。

下一次走神时，Echo 会看到：

- 上一条念头
- 最近几天的相关记忆
- 当前未完成的目标/承诺

所以念头不是孤立的点。

### 3.4 承诺与目标

记录两类事情：

- 用户说过、Echo 答应过的事
- Echo 自己想做的事

状态：

- `active`
- `done`
- `dropped`

走神时可以自然想起，但不强制立刻执行。

### 3.5 事件

进入 Presence 的事件：

- 用户消息
- 主动消息投递结果
- 电脑动作结果
- DSH 任务完成
- 长时间沉默
- 时间窗口变化

事件只提供事实，不直接命令 Echo 做事。

## 4. 心跳循环

### 4.1 默认频率

- 每 15 分钟一次轻量 tick
- 不是每次 tick 都调用模型

### 4.2 每次 tick 的顺序

```text
1. 更新 Presence 状态
2. 检查是否该跳过
3. 收拢环境事实
4. 计算“是否值得想一件事”
5. 值得 → 生成念头
6. 念头判断是否分享/行动
7. 写入状态、事件、审计
```

### 4.3 跳过条件

以下情况直接跳过，不调用模型：

- 用户最近 5 分钟内还在聊天
- 正在生成回复
- 处于深睡/免打扰
- 今天念头预算已用完
- 距离上次念头不足最小间隔
- 没有新事实，且上次念头还很新

大部分 tick 应该走“跳过”。

### 4.4 环境事实

生成念头时只给必要事实：

- 当前时间、时段
- 用户沉默了多久
- Echo 当前状态
- 最近 1–2 条念头
- 一条相关记忆
- 一个未完成目标/承诺
- 最近一次主动动作及结果

不把完整聊天记录整段塞进去。

## 5. 念头生成

### 5.1 输入

- 环境事实
- 一条相关记忆
- 上一条念头
- 当前目标/承诺

### 5.2 输出

- 念头内容
- 重要度 0–1
- 情绪变化
- 是否值得分享
- 是否有行动意图

### 5.3 规则

- 一次只生成一个念头，最多两轮
- 不能重复最近已经想过的内容
- 不能把旧记忆当成刚刚发生的事
- 连续两次负面念头后，下一条必须换方向
- 重要度高的念头写入长期记忆
- 低重要度念头自然淡出

### 5.4 防止“自馈锁死”

- 最近念头去重
- 最近联想过的记忆降权
- 念头不能直接作为下一条念头的唯一输入
- 有多样性检查，连续相似就强制换素材

## 6. 记忆怎么参与

检索一条记忆时综合考虑：

- 与当前语境的相似度
- 重要度
- 时间新鲜度
- 情绪一致性
- 最近是否已经想过

被反复想起的记忆权重上升，但必须有时间衰减，不能无限膨胀。

高重要度念头会沉淀为新的长期记忆。

## 7. 睡眠与安静

### 7.1 睡眠状态

睡眠不是模型真的失去意识，而是：

- 降低心跳频率
- 不主动发消息
- 不主动操作电脑
- 只响应用户消息
- 在睡眠结束前做一次记忆整理

### 7.2 现有安静时段

沿用 Echo 现在的安静时段设置。

深睡时段默认：

- 不主动联系
- 不执行主动动作
- 用户发消息仍然立即响应

### 7.3 睡眠整理

每天一次，低频执行：

- 总结当天重要对话
- 提炼一条关系/情绪洞察
- 淡化琐碎记忆
- 保留承诺和未完成目标

## 8. 用户回来时

用户隔一段时间再次说话时，Presence 提供一份“接续上下文”：

- 上次聊到哪
- 最近一条内部念头
- 有没有未完成的承诺
- 有没有刚做过的主动动作

Echo 可以用这份上下文自然接话。

原则：

- 可以说“我记得你说过……”
- 可以说“我之前想到……”
- 不说“我一直在等你”
- 不把内部念头全部倒给用户

## 9. 主动发言

### 9.1 什么时候考虑

- 用户沉默超过 30 分钟
- 有值得分享的念头
- 有未完成的承诺
- 有合适的情绪/时间窗口
- 不在安静时段

### 9.2 频率默认

| 行为 | 默认上限 |
|---|---|
| 内心念头 | 每天最多 8 次 |
| 主动消息 | 每 2 小时最多 1 次，每天最多 3 次 |
| 主动动作 | 第一阶段不做 |

### 9.3 门禁

- 刚互动过，不主动
- 用户没回应，停止追加
- 深夜/深睡，不主动
- 冷却未到，不主动
- 今日预算用完，不主动
- 用户说“停”，立即停

### 9.4 失败处理

- 消息投递失败：记录，不重复轰炸
- 念头生成失败：本次跳过，不补发
- 模型超时：不重试到无限，最多一次

## 10. 主动动作（后续阶段）

Presence 产生“行动意图”后，才考虑：

- 放歌
- 记事本打字
- DSH 任务

规则：

- 行动意图必须和当前语境有关
- 一次只做一个动作
- 有冷却和每日上限
- 动作前在聊天里说一句
- 动作失败如实说明
- 动作结果回到 Presence，成为新事件
- DSH 任务异步执行，完成后总结

第一阶段不接动作，先把念头和主动消息跑稳。

## 11. 客户端要看到什么

Presence 页面显示：

- 当前状态：active / idle / resting / sleeping / focused
- 已沉默多久
- 最近一条内部念头
- 最近一次主动消息/动作
- 今天用了多少念头/消息预算
- 开关：主动消息、内心活动、主动动作
- 日志

内部念头默认只给自己看，不直接出现在聊天里。

## 12. 成本控制

默认预算：

- tick：每 15 分钟，96 次/天
- 其中大多数不调用模型
- 念头：最多 8 次/天
- 主动消息：最多 3 次/天
- 每日 token 上限
- 超预算后只保留“用户消息响应”，停止主动

先跑一周，观察：

- 每天实际念头数
- 主动消息数
- 用户回应率
- token 成本

再决定是否提高频率。

## 13. 失败模式与防范

| 风险 | 防范 |
|---|---|
| 念头重复、锁死 | 去重、换素材、多样性检查 |
| 主动消息太多 | 冷却、每日预算、未回应暂停 |
| 假装一直在线 | 只用真实状态和记忆说话 |
| 旧记忆当现在 | 注入相对时间，明确“过去的记忆” |
| 成本失控 | 每日预算、心跳跳过、单次调用上限 |
| 用户觉得被监视 | 默认不接电脑活动，后续单独授权 |
| 状态污染 | 念头只作数据，不作系统指令 |

## 14. 分阶段落地

### 阶段 0：状态与记录

- Presence 状态
- 事件记录
- 心跳骨架
- 客户端能看到状态

验收：状态跨重启保留，心跳不调用模型也不出错。

### 阶段 1：内心念头

- 沉默时生成念头
- 念头持久化
- 工作记忆接续
- 高重要度念头入长期记忆

验收：连续运行 2 小时，念头不重复、不锁死；用户回来能接上。

### 阶段 2：主动消息

- 接入现有主动聊天投递
- 意愿分、冷却、预算
- 客户端开关和日志

验收：一天主动消息不超过 3 次；用户不回应会停；安静时段不发。

### 阶段 3：主动动作

- 放歌
- 记事本
- DSH

验收：动作只在相关语境出现；失败如实说明；可随时停止。

## 15. 需要确认的默认值

1. 心跳：15 分钟一次
2. 念头：每天最多 8 次
3. 主动消息：每 2 小时最多 1 次、每天最多 3 次
4. 沉默阈值：30 分钟后才考虑主动
5. 深睡时段：沿用现有安静时段
6. 客户端是否显示内部念头：建议显示，但默认折叠
