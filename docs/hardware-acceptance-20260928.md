## 真实设备证据

本地后端观察到 `192.168.137.190`：

1. `POST /devices/firmware/config` 返回 200。
2. 建立 `/devices/ws` WebSocket，数据库记录设备已绑定且 online。
3. 三次实际 `self.get_device_status` MCP 检测均收到匹配回执：
   HTTP 200、`acknowledged=true`，分别 25、48、43 ms。
4. 使用 USB 使实际设备进入引导模式。检测 HTTP 504、
   `acknowledged=false`，没有将“指令发出”误判为硬件成功。
5. 恢复启动后真实回执恢复；再测三次分别 25、72、47 ms。

这里没有使用模拟 WebSocket。检测通过仅说明网络和 MCP 响应链路通畅，
不代表已验证麦克风采集、扬声器听感或声纹准确率。

可重复执行：

```powershell
python scripts/run_device_lab.py --hardware-lab
python scripts/check_hardware_lab.py --probe
```

后端已运行时不要再启动第二个实例。需要验证重启时执行：

```powershell
python scripts/check_hardware_lab.py --probe --reboot-probe
```

最后一个命令会短暂中断硬件，不要在录音或语音交互过程中执行。
诊断脚本只使用本地验证码登录，凭据不输出、不写文件。
短时间重复运行可能触发本地短信登录限流，应等待后重试。
