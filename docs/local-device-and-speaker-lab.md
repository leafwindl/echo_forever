## 2026-09-29：App 初始录入与 Echo 硬件校准

App 完成三段初始录入和第四段独立验证后，在人员详情中选择
“开始硬件校准”，取得本人同意，并由本人对在线 Echo 朗读 App 显示的
三句采样句和第四句验证句。Echo 每段回播结果；失败不推进进度，
可以重读当前句。每台设备同时仅有一个十分钟的本地会话；
取消、断线和过期不保存未完成样本。校准写入独立的设备向量，
不替换手机样本；删除硬件校准会回退手机向量。删除人员同时删除硬件向量。

校准完成前不根据手机/硬件跨麦克风低相似度强行认人。识别结果仅用于称呼；
非主人没有账号记忆、历史或工具权限，声纹也不是身份认证。
本轮通过隔离数据库接口、会话状态机和 Echo Dev 构建安装测试，
**尚未由真人完成 Echo 四段朗读与后续盲测**；阈值仍属暂定值，
不能据此声称识别准确率达标。未部署生产。

## 1. 本轮范围

- 原“一键连接”改为可选的“设备检测”。不再暗示能替设备联网、绑定或切换 Wi-Fi。
- 检测前提：设备已绑定且与当前后端建立 WebSocket。后端发送
  `self.get_device_status`，最多等待 5 秒，必须有当前会话的匹配 MCP 回执。
- 离线、拒绝、断线、超时或空回执均不能显示成功。检测成功不代表音频播放、
  麦克风、声纹识别或全部硬件功能正常。
- App 可新增家人/朋友称呼、查看进度、继续录入、删除声纹。
- 旧统计特征档案不迁移为真实声纹；旧录入 API 返回 410。

## 2. 录入与识别

App 流程：填写称呼、取得录入者同意、录制三段不同语音、第四段独立验证。
前三段生成归一化中心向量，第四段不参与中心向量训练。
录音要求为 PCM16LE / 16 kHz / 单声道 / 3–12 秒；App 在 10 秒自动停止。
质量错误、模型不可用、重复提交、说话人不一致均不增加进度。

硬件流程：

1. 主动说“记住我的声音”。
2. Echo 询问称呼。
3. 明确说“我同意”；含糊的“好的”不作为同意。
4. 设备管理员打开 App 的“人员声纹”，批准本次录入。
5. 对 Echo 说“开始录入”，按提示录三段，再做第四段验证。
6. 可以说“取消录入”；取消不自动删除此前已保存的档案，需在 App 删除。

每设备一个会话，全局最多 64 个，10 分钟过期；断线、重连或重启不自动恢复。
已经开始处理的片段可能在取消时保存，但取消后不再继续引导或新增片段。
App 每 3 秒刷新请求和人员列表。当前本地模式必须使用一个后端 worker。

每设备最多 20 人。数据库仅保存特征、录音 SHA-256、模型标识、同意时间和进度，
声纹流程不存原始 PCM。现有 ASR/TTS 可能使用配置中的外部服务，因此不是全离线系统，
也不能把本地“不保存 PCM”解释为外部供应商的保留政策承诺。

识别仅比较当前设备、当前所有者的有效档案。低分返回 unknown，前两名过近返回
uncertain，不强行猜人；声纹不授予 owner 权限，也不作为登录或敏感操作认证。

## 3. 模型与资源

- 模型：sherpa-onnx 提供的 3D-Speaker CAM++ 中文 ONNX。
- 运行时：`sherpa-onnx==1.12.26`，独立 Python 环境，CPU 单线程、单实例。
- 本地文件：`data/speaker-models/campplus-zh.onnx`，28,281,138 字节。
- SHA-256：`f682b514c05d947ee3fa91cd6ec6c5c7543479a128373fa29b1faedccd21fd11`。
- 192 维 embedding；模型指纹不一致必须重新录入，不混用。
- 初次加载测得工作集约 118 MiB、私有内存约 578 MiB，不能仅按模型文件大小估算。
- 4 秒合成信号一次推理约 121 ms，仅证明链路和一次性能，不证明识别准确率。
- 相似度 0.65、前两名间隔 0.12 均为临时阈值，尚未用家庭真实录音校准。
- 能量与削波检测不是完整语音 VAD，也不是重放攻击或合成声音防护。
- 模型服务忙返回 429；请求体有大小上限与 5 秒上传期限；后端请求超时 8 秒。

## 4. 本地启动

以下 PowerShell 命令从 `F:\project_work\AI_Chat` 执行。需要现有
`echo-postgres-test` 容器，仅允许它映射到 `127.0.0.1:15432`。
独立数据库名为 `echo_device_lab`，不读取生产数据库。
脚本只在内存读取本地容器密码，不输出或写入文件。

```powershell
docker start echo-postgres-test
python scripts/run_device_lab.py --init-only

$env:PYTHONUTF8='1'
$env:ECHO_SPEAKER_MODEL=(Resolve-Path 'data/speaker-models/campplus-zh.onnx').Path
$env:PYTHONPATH=(Resolve-Path 'scripts').Path
& 'data/speaker-venv/Scripts/python.exe' -m uvicorn speaker_service:app --host 127.0.0.1 --port 18100
```

另开终端：

```powershell
$env:PYTHONUTF8='1'
python scripts/run_device_lab.py
```

初始化和启动含数据库结构变更，不要在正在联调或跑测试时并发执行。
测试命令不再重新执行建表迁移：

```powershell
python scripts/run_device_lab.py --test
```

后端健康检查：`http://127.0.0.1:18000/health/ready`。
模型健康检查：`http://127.0.0.1:18100/health`。
本地登录验证码固定为 `123456`，不发送真实短信。
JWT 密钥仅保存在当前进程内，后端重启后需重新登录，账号和声纹数据仍保留。
本地数据不会包含生产设备列表，不能据此判断生产绑定丢失。

## 5. Android 调试

从 `app` 目录执行：

```powershell
flutter build apk --debug --no-pub --dart-define=ECHO_ENV=development --dart-define=ECHO_BASE_URL=http://127.0.0.1:18000 --dart-define=APP_VERSION=1.1.7-local
adb -s ce7f6baf reverse tcp:18000 tcp:18000
adb -s ce7f6baf install -r build/app/outputs/flutter-apk/app-debug.apk
```

实际包名 `cn.echoaiforever.echo_app.debug`，桌面名称 Echo Dev；
包版本来自现有 pubspec，为 `1.1.7-debug+23`，未改生产发布版本。
`APP_VERSION` 是编译环境值，不覆盖 Android 包元数据。
已安装到 PJC110，并观察到手机对本地后端的登录、设备列表请求成功。
没有清除正式 App、Dev 数据或硬件 NVS，没有刷入新固件。

注意：ADB reverse 仅覆盖手机，不覆盖 ESP32。
初版硬件仍指向生产服务；后续已使用隔离的本地固件和 `--hardware-lab`
双地址监听完成网络检测。不能直接用上述 localhost 地址完成硬件联调；
不要把生产 claim token、凭据或绑定记录直接复制进本地数据库。
后续需单独设置硬件可访问的本地地址及测试绑定，保留原配置以便恢复。
