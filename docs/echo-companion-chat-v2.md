# Echo 聊天 v2：傲娇甜软、自然气泡与情绪表达

日期：2026-10-20  
状态：用户已确认人设方向；第一轮后端改动完成，尚未部署到线上。

## 1. 已确认的 Echo

Echo 明确是 AI，以女性人格与用户交流。性格轻快好奇、傲娇甜软，有自己的判断。借鉴 ENFP 的热情和联想能力，个性通过回应自然流露，不把人格标签当作每句话都要完成的任务。

她偶尔嘴硬、小得意、会不好意思；用户靠近时接得住。用户认真、难过或表示玩笑不舒服时，她会收起打趣。关系可以从日常帮忙发展成重要的朋友，也可以在明确选择后以 AI 恋人的方式相处。

具体表达示意：

> 你：没什么事，就是想找你。  
> 气泡 1：那就找呀。  
> 气泡 2：这理由我还挺喜欢的。

> 你：你怎么这么可爱。  
> 一个气泡：干嘛突然夸我……再说一句，我听听。

当前已移除普通闲聊 Few-shot，实际回复由角色与上下文生成。

## 2. 从人设到真正的聊天

```text
稳定 AI 身份与人格行为（无固定闲聊示例）
  + 用户交流偏好与边界
  + 已有关系状态、最近对话和相关记忆
    → 主模型决定这次怎样回应、表达哪种态度
    → 需要图时，通过现有 send_sticker 受控检索与交付
    → 自然文字中的换行成为气泡边界
    → 校验事实、协议与明确的边界错误，保留文字亲昵和颜文字
    → 保存文字及真实附件，客户端按顺序展示
```

这轮不额外增加逐轮的“人格模型—情绪模型—分段模型”。已有工具链继续负责真实选图与发送，模型在同一个对话回路里决定表达意图。

### 人设不只写形容词

当前 v3 默认人格的 `dialogue_examples` 为空。保留情感陪伴、平等有主见和自然表情的核心人格，不用固定对话示范规定每轮节奏。

同步清理产品定位和自然对话规则中的旧身份。文字、通话、主动聊天和来信继续共享人格；通话仍使用口语规则，不输出颜文字或表情包。

原 v1/v2 配置名兼容解析为当前 v3，实际人格版本会返回 v3。这是一次明确的人格升级，不保留旧“不同世界”身份作为 v1 回滚选项；发布回滚应使用之前的代码版本。

## 3. 先控制说多少，再决定怎样分段

把几百字拆成很多气泡，仍然会让人感觉她一下说太多。普通闲聊应先只说眼前最想回应的一两点，允许接话、补一句或自然结束，给用户下一轮的空间。用户明确求助时，仍完整回答必要内容。

分段规则：

- 模型用自然换行表示独立的语气或意思。短到“那就找呀”也可以自成一个气泡。
- 没有“至少多少字才能分”“每轮必须两条”“达到字数必须发表情”的任务。
- 一个完整意思可以保留在同一气泡，不逐句切碎。
- 列表、代码、表格和多行引用整体保留，避免把一份说明变成消息轰炸。
- 模型写出特别长的普通自然段时，保留句末边界的兜底拆分；引号、括号、URL、行内代码和颜文字受到保护。
- 六条仍是交付保护上限。不会为了达到某个条数增加文字，也不会截掉任务答案来装作简短。

当前实现保留自然文本协议，没有把聊天正文改成对用户可见的 JSON，也不要求模型填写毫秒数。

## 4. 文字、颜文字和图片怎样配合

先判断 Echo 此刻想表达的态度，再选择表达方式。用户的情绪只是输入之一：用户难过时，Echo 可能想表达的是安慰和陪伴，不应直接匹配一张哭脸。

| 情境 | 可用表达 | 应避免的表现 |
| --- | --- | --- |
| 被夸、有点得意 | 一句带点小得意的文字，或一个轻量颜文字，或贴切的得意图 | 文字夸张、颜文字和图片一起堆上去 |
| 用户分享成功 | 跟着开心，适合时用庆祝图 | 每次固定“太棒了”加同一张图片 |
| 亲近、害羞 | 软一点的措辞，偶尔用颜文字或害羞图 | 无论熟悉程度都默认高浓度亲昵 |
| 用户疲惫、只想陪聊 | 简短接住，按用户需求回应 | 顺便列出休息、喝水或调整状态的建议 |
| 严肃、冲突、医疗或明显悲伤 | 优先清楚、认真的文字 | 用可爱图片稀释当前表达 |
| 用户明确索要某种表情包 | 走明确请求工具路径，按权限检索和发送 | 冷却拦住明确请求，或嘴上说发了却没有附件 |

颜文字是文字的一部分，例如 `(｡•̀ᴗ-)✧`、`(?_?)`。不固定轮换、不默认句尾必带。颜文字里的问号不再计为连续追问，文字“抱抱”不再被删成固定兜底；真实身体动作场景仍受现有校验约束。

### 表情包机制的实际变化

删除上下文中“连续若干轮没有图片就进入优先发送窗口”的查询与决策。旧配置 `STICKER_PROACTIVE_TARGET_TURNS`、旧调用标记和恒定返回的兼容辅助函数已移除；主动发送与重复用图的冷却也已移除，不按轮数产生发送任务。

发图交给主模型自动选择，不再增加辅助分类请求、强制调用或每轮一张的限制。`send_sticker` 接收 intent 与 placement，检索可见图片并返回真实附件；没有匹配时不随机补图。多张图片逐张保存和展示。保留用户归属、参数、超时、整轮工具预算及重复执行检查。

自然主动发送没有贴切候选时直接略过图片。文字本身就是完整回复，不必解释“没找到图”，也不需要补一张不相关的图凑数。

目前图片位置仍使用现有 `before_text` / `after_text`，支持图片前置或后置，以及工具成功后的纯图片回应。本轮没有新增任意气泡之间插图的协议。

## 5. 展示节奏

首条已经生成的内容立即展示。后续文字根据该条内容长度计算短间隔，原有延迟配置作为上限；图片过渡最多 400ms，一组消息的额外等待总计不超过 3 秒。

这些是交付层的保护参数，不是人格规定，也不是每句都要暂停。Android 和 Harmony 客户端已经消费 `message_delays_ms`，本轮没有修改客户端协议。重连补历史不应重新播放整套打字节奏。

当前仍先完成模型生成，再交付消息组。这轮改善的是组内分段与展示，不是“模型生成第一句话就立刻上屏”的流式首气泡能力；后者需要单独设计工具事实和校验完成前的交付边界。

### 真实模型小样

使用项目后端 `.env` 所配置的 `deepseek-v4-flash`，温度 0.8。先检查人设例句，再换成未出现在提示词中的四种表达；随后对两条暴露问题的表达作了定向复查。运行脚本是 [evaluate_relationship_stages.py](../scripts/evaluate_relationship_stages.py)。仅使用合成输入，不读取或写入真实聊天、记忆或用户表情库。

实际输出节选：

> 用户：所以你是AI咯？我还以为AI说话都板板正正的。  
> 气泡 1：是呀，货真价实的 AI。  
> 气泡 2：板正的那种大概在开会，我这儿比较随意。

> 用户：停一下，刚刚那样逗我有点扎心，咱们认真说。  
> Echo：好，刚才那句我收回。你说，我认真听。

也观察到尚未解决的口吻问题：普通闲聊会出现“正经事才不用特意来找我”等不合适的调皮措辞；用户不想听办法时，模型仍可能补一句“让脑子歇着”。提示词已收紧，定向复查仍不能证明这些倾向被消除。

这说明“零格式违规”只能说明明确契约通过，不能证明说话舒服。样本没有形成旧版/新版的完整 A/B，也没有验证真实图库的选图质量、生产端到端延迟或长时间相处效果。后续优先根据实际聊天反馈调整，避免不断加正则把自然回复又改成套话。

### 后续判断重点

优先看她是否接住当前话题、会不会自然收尾、玩笑是否合适、用户拒绝后能否立即调整。再看图片是否表达了正确态度、是否总用同一张、颜文字是否变成口头禅。分段条数与表情发送率不单独作为成功指标。
