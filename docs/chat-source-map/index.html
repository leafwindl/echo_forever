    RULE CROSSWALK / 定义与检查对照

    一条规则，沿着四个位置查。

    先读定义，再看执行与断言。这里记录的是测试位置，不是测试通过状态。

    规则在哪里定义在哪里执行或检查对应测试 · 未运行实际边界

    先记住三个区别

    理解上下文，最容易混淆的是这些。

    01 / 找到定义，再看执行

    改了一句 Prompt，不代表增加了运行门禁。先定位定义，再检查谁消费这条规则、如何处理失败。

    02 / 生成内容，保留出处

    记忆和摘要是模型产物。需要能回看用户原话、保存边界与生成规则；背景标记不能替代事实核验。

    03 / 测试存在 ≠ 已验证通过

    有些测试只断言文案存在，有些验证假模型与执行器。既要查看断言内容，也要实际运行，不能据文件名认定覆盖完整。

    依据与范围：基于当前工作区代码阅读，查看关键文件

    本页基于当前工作区的常规文字聊天代码。文件和定位符在构建时检查存在，行号是构建时快照；代码修改后行号可能变化。未读取 .env 内容、用户数据库或部署密钥；不展示私人数据。未运行后端测试、真实模型评测或安全审计。规则测试均为“已定位、未运行”，不是通过报告。

    节点、边、分组与布局意图来自语义 JSON。页面内置 Dagre 1.1.5 自动布局引擎，渲染器根据引擎输出生成 SVG；未为具体图表手工指定坐标。导出的 JSON 不含坐标、尺寸或路径。渲染器采用折线路由，分组以标签与节点说明表达，不强制聚类边框。所有脚本与样式内嵌，禁止页面发起网络连接。
