# System 模块

## 1. 业务目标

承载系统级接口，提供存活检查、数据库就绪检查和发布版本信息。

## 2. 核心业务流程

1. 应用启动时注册系统接口。
2. 客户端请求健康检查地址。
3. 存活检查不访问依赖；就绪检查执行轻量数据库查询。
4. 调用方根据返回结果区分“进程存活”和“业务依赖可用”。

## 3. 对外契约

### HTTP API

- `GET /`
  - Response: `{"status": "ok"}`
- `GET /health/ready`
  - 数据库可用时返回 HTTP 200。
  - 数据库不可用时返回 HTTP 503，且不暴露连接异常细节。
- `GET /version`
  - 返回 `APP_VERSION` 和 `BUILD_REVISION`。

### 发布的事件

- 当前无已落地事件。

### 依赖的其它模块接口

- `APP_VERSION`
- `BUILD_REVISION`

## 6. 注意事项

- System 模块不承载用户业务流程。
- 存活检查和依赖就绪检查必须保持独立。
